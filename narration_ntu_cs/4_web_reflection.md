# Django 訂單管理系統：從 0 到 1 的全端開發與架構思維

## 動機與介紹
高二暑假初，為改善母親工作場所繁雜的 Google 表單與 Excel 流程，我接下委託開發訂單管理系統。在此之前，我只會寫簡單的 Python 爬蟲與基礎網頁。這是我的第一個大型專案，首次挑戰涵蓋前端（HTML/CSS/JS）、後端（Django）、資料庫（SQLite）與伺服器部署的完整開發。面對龐大知識缺口，我透過線上資源一步步建構系統，最終打造出具備多種權限管控、統計圖表與 AI 助理的完整平台。

## 開發流程
1. **基礎建構**：釐清系統需求，學習資料庫與django。
2. **系統雛形**：規劃架構，建立 Django 路由與基礎前端頁面。
3. **資料庫與邏輯**：重構資料庫，實作身分驗證與訂單管理。
4. **功能優化**：用Django Forms重寫表單功能，並擴充動態分頁、統計圖表
5. **版控與部署**：導入 Git 進行版本控制，並於 Render 雲端平台完成系統部署上線。

## 遇到的困難與解決方案
| 遇到的困難 | 解決方案與學習收穫 |
| :--- | :--- |
| **資料庫難以維護**：初期用原生 SQL，系統變大後查詢與修改極度麻煩 | 改用 Django ORM，重新設計並釐清商品、訂單與使用者權限的資料關聯。 |
| **表單處理繁瑣**：純 HTML 表單在驗證與修改流程上非常麻煩 | 導入 Django Forms 處理表單，提升安全性與開發效率。 |
| **技術卡關頻繁**：依賴網路零碎教學或 AI 片段解答，難以解決根本問題 | 培養耐心直接研讀官方文件，理解框架底層邏輯，成為最重要的自學技能。 |
| **程式碼管理混亂**：開發過程中常面臨程式碼遺失或改錯無法還原的風險 | 主動學習 Git 版本控制，解決版本回溯問題。 |
| **缺乏上線經驗**：不知如何將本地端程式變成實際供人使用的產品 | 自學 Render 雲端部署與環境建置，成功將系統上線。 |

## 心得與反思
在這個專案中，我深刻體會到「主動學習」的重要性。回顧這次從 0 到 1 的開發經驗，我不僅初步建立了「後端架構設計」的思維（體會到資料庫關聯與模組分離對專案維護的影響），更培養了獨立解決問題的能力。在無人指導的環境下，我透過主動研讀官方文檔來克服技術瓶頸。這段經歷不僅讓我掌握了技術，更建立起持續學習的習慣與自信心，為我後來參與 AIS3 Junior 等進階挑戰，打下了最堅實的基礎。

---
**專案成果與獲得能力總覽：**
- **核心功能**：登入與身分驗證系統、使用者/管理者權限分流、訂單自動統計圖表。
- **使用者端**：商品下單、查看同類別訂單、AI 助理（輔助查詢商品/訂單與下單）。
- **管理員端**：全平台訂單檢視與刪除、使用者與商品資料庫的 CRUD（增刪改查）。
- **獲得能力**：基礎前後端開發、資料庫設計與關聯規劃、基礎架構設計、官方文檔閱讀能力、Git 控管與部署。
