# devjam 2025
## 前言
在 Google Developer Groups (gdg) on campus DevJam tw 2025 中，我以後端與 AI 應用工程師的身份，跟組員們一起努力，拿下了 Gemini API 組的第一名。這次比賽帶給我最大的收穫，其實不是我又寫出了多複雜的架構，而是真真切切地體會到**在產品導向的比賽裡，精準找出痛點、提供完整的解決方案跟一份有說服力的報告，遠比任何技術細節都來得重要。**
<img src="https://hackmd.io/_uploads/Sy_PMMSsZe.jpg" alt="20260328_163242" width="400">

## 開始
我們這組的組成還滿特別的，我主動負責全部的後端跟雲端部署，搭配一位負責前端的清大資工學長，另外還有兩位負責企劃跟簡報的政大文組學長姐。
這次主題是「ESG+」，說實話對我來說超級陌生。

一開始在一起想題目的時候，我一直丟出各種我覺得很酷、技術上很有挑戰性的點子，但政大的學長姐總能敏銳地指出這些點子在現實應用上的盲點。來回幾次之後，我坦白說覺得有點煩了，索性就放手讓他們決定主題，想說我專心當個開發的工具人就好。最後，他們決定做一款「海外留學顧問 AI」，主要功能是整理各校資訊、輔助做備審跟自動提醒時程。當下我心裡其實覺得這點子也太普通了吧，但為了能趕快開工，我還是點頭同意了。

## 挑燈夜戰的極限開發
進入開發階段後，**我迅速用 python FastAPI 寫出最基礎的 AI 調用並生成 API 文檔，交接給負責前端的學長**，但接著我就卡關了，卡在 Google Cloud 的部署上。我在環境變數跟連線權限那邊搞了超久，重弄了一個多小時才總算讓前端連上。

接下來在實作像是自動行事曆、檔案管理這類比較進階的功能時，開發節奏就更慢了。除了邏輯本來就比較複雜，我跟前端之間的溝通也有一點斷層，導致我們有一段時間都各做各的。不過黑客松的夜晚其實滿好玩的，可以一直去拿免費的零食飲料，還解鎖了在各種奇怪角落寫程式的成就，我一路從位子換到窗台的休息小床繼續趕工。

政大的學長姐在晚上八點左右先回去睡覺，留我跟前端學長繼續拼。雖然學長對 API 串接不太熟，加上我自己手腳也有點慢，過程滿驚險的，但我們還是奮戰到了午夜三點多，最後在凌晨四點完成最後的整合與測試，才跑去稍微睡了一下。


## 跨領域的完美分工
早上八點，政大的學長姐回來接手，這時候就是他們大顯神威的時間了。他們在超級短的時間內，把我們連夜生出來的產品，轉化成一份架構超清楚、乾淨又漂亮的簡報。簡報裡精準打中了留學生的痛點，從系統架構、未來展望到整個商業模式都講得很有說服力。這真的是我這種純技術人員完全做不到的，我只能在旁邊幫忙修飾一下技術名詞而已。

上台報告的時候，學長姐那個氣場跟專業度真的很穩。報告完整到評審幾乎不需要多問什麼，就算有提問他們也能完美應對。就靠著他們無懈可擊的台場表現，我們就這樣得到了冠軍。


## 產品：申寶 SAMBOU

我們的產品叫做「申寶 SAMBOU」，簡單來說就是為了解決留學資訊太碎、代辦費又太貴而做出來的 AI 留學平台。主打「搞定留學大小事，不用再戰第二次」。
<img src="https://hackmd.io/_uploads/SJomBEnjWx.jpg" alt="9" width="600">

我們實際做出來的東西大概是這樣：

1. **直擊痛點**：台灣每年想出國留學的人很多，但代辦真的太貴，各國規定又很複雜。我們就是針對這個問題給出解方。
2. **AI 顧問建檔與選校**：我們用 Agentic Flow 技術引導使用者輸入 GPA 跟經歷來建立個人檔案。然後結合 Gemini Deep Research 跟 RAG 來幫忙精準媒合跟評分最適合的學校。
3. **自動潤稿與文件管理**：前端用 Angular 寫的 SPA，後端就是我寫的 FastAPI 加上 Firebase 資料庫，最後部署在 GCP 上。我們也利用了那時候剛出的 Gemini 2.5 具備超大上下文視窗的優勢，丟給它長篇的申請文件來幫忙提供 SOP（讀書計畫）的修改建議。
4. **商業模式**：採 Freemium（免費增值）模式，基礎的 AI 顧問跟選校免費，進階排程跟潤稿才收費。
5. **社會願景**：未來除了與語言學校、航空金融業等進行異業結盟，也能對接政府的「青年百億海外圓夢計畫」。長遠目標是建立 AI 驅動的教育生態系，實踐 SDGs 消除貧窮與優質教育的社會影響力。

## 心得與反思
這次比賽真的徹底翻轉我對做專案的認知。以前我都習慣從「我想寫什麼功能」出發去想題目，但經過這次， **我明白了訂題目必須從有數據證明的真實痛點出發，而不是開發者自己想出來的假痛點。 確認目標客群後，再提出具備可行性的解決方案，並證明它真的能解決問題。**
**我也發現了在這種以產品為主的比賽中，只要契合主題、選擇簡單但扎實的題目，並把「問題與解決方案」設計好，就能取得好成績。不需要冒險去做前所未見或是異想天開的產品，即便是看似普通的點子，只要能確實解決痛點，就是一個好的專題。我一定會把這次學到的經驗，應用在未來所有產品導向的專題比賽中。**
同時，**我也學到了進階的團隊合作**。一開始，因為兩位政大的學長姐沒有充足的開發經驗，清大的學長也主要依賴 Vibe Coding 寫前端，我原本對得獎不抱期望。但事實告訴我，技術並不代表一切，就算有技術，無法做出好產品也無法獲勝。我們這組達成了最完美的分工合作：懂技術的專心搞技術，懂企劃的專心搞定文案與簡報。大家都在自己擅長的領域發揮到極致，最終在有限的時間內，完成了這個冠軍產品。 **在與學長姐交流及觀摩的過程中，我也從旁學會了如何製作一份架構明確、直擊痛點且極具說服力的簡報，彌補了我以往只專注程式開發的不足。**
